Due 3 · Tooltip actions. The glyph is the control. Tapping it opens a rich tooltip carrying the one fact the row can't show (when) plus the one or two actions that only make sense for a scheduled task. It's the same TooltipBox the Claude receipt already uses, so this is a second instance of an existing pattern rather than new chrome.

Why not the ⋮ menu? It's right there and already holds five entries. But the schedule actions are about this row's time, and the tooltip is where the time is already being shown — splitting "when" into a tooltip and "reset it" into a menu three pixels away is worse than putting both in one place. The counter-argument is real though, and it's exactly the Delete question in state B.

Three actions is the ceiling. richTooltipMaxWidth is 320dp and the action row is a single line, so two labels of this length fit comfortably and three is tight. If a state needs more, it wants a dialog instead.

Persistent tooltips steal the next tap. With isPersistent = true the tooltip stays until dismissed, and the outside tap that closes it is swallowed by the popup — so the first tap after reading it does nothing to the list. That's correct behaviour and still surprising; worth feeling on device before committing.

1.4.0 renamed caretSize → caretShape. The old parameter survives only as a hidden binary-compatibility overload, so source that copies an older sample won't compile. Use TooltipDefaults.caretShape() and rememberRichTooltipPositionProvider(), not the plain one.
