Widget — matched to Redesign 1 (Slack Rail)

The app rail can't be copied wholesale: RemoteViews has no press state, no popups and no horizontal scrolling, so the row action bar has no widget equivalent. What does port is the emoji tile — and it fixes a live bug. WidgetPill is wrap_content inside a plain LinearLayout with no scroll container, so today MAX_PILLS = 8 is aspirational: on a 4×2 only about three name pills fit before the rest clip off the right edge. A 32dp emoji tile fits six or seven in the same space.

What ports from Redesign 1, and what doesn't

App featureWidgetWhy
Emoji section tile ✓ ports Emoji is just text — setTextViewText on the existing pill TextView. No new drawable, no renderer restructure. Same nullable emoji column, same initial fallback.
Per-section open counts ✓ ports A badge TextView per slot. Needs a count query per section — the renderer currently only loads items for the active section (listItems(active.id)), so this is a new DAO count-by-section.
Vertical rail ~ 4×3+ Possible as a fixed-slot vertical LinearLayout, but 44dp of ~350dp is too much at 4×2. W1 for small sizes, W2 for large.
Press-reveal action bar ✗ can't RemoteViews has no press state, no hover, no popup/anchored menu. The widget keeps tap-to-toggle. Splitting check from open-app is possible though — a separate setOnClickFillInIntent on item_checkbox vs item_text, instead of today's single one on item_row.
Link thumbnails ✗ can't Two blockers: setViewTypeCount(1) means every row shares one layout, and RemoteViews can't fetch a network image — it needs setImageViewBitmap with a bitmap decoded in-process. Widget stays text-only on item.displayText, which is already the behaviour.
Boxed composer + tool rail ✗ can't No text input in RemoteViews. Add stays a PendingIntent into QuickAddActivity, which is Compose and can carry the redesign properly.
Move-to-section ~ later No per-row menu to hang it on. Would need a long-press → activity, and RemoteViews collection rows only support click, not long-press.
